# 导弹型号识别

[导出指南](acmi-export.zh-CN.md) · [制导信息](ACMI_GUIDANCE.md) · [型号证据](evidence/missile-models.md)

导弹型号识别默认开启，用于补充回放对象的具体型号及候选信息。`WT_WeaponID` 是当前回放中的武器索引，不是所有回放共用的型号编号，因此不能直接将一份回放的数字 ID 映射用于另一份回放。

## 识别依据与优先级

导出器结合以下证据进行识别：

1. 根据击杀报告中的攻击者、导弹结束时间，以及同一回放的非零原始构造标识、模板及武器类别建立型号关联。
2. 使用精确内部名别名识别击杀记录中的型号，不按名称前缀或发射顺序推测。
3. 仅在完整 WRPL 的 SHA-256 匹配时，启用特定回放的 ID 表。高置信条目可以补充具体型号，中低置信条目只保留候选；已有击杀型号优先。

4. 型号仍未知时，结合已解码导引头及实际挂载，或精确载机的可挂载槽目录，推断同一弹族的基础型号（如 `AIM-120`），标记 `Inferred` 并保留未分变体标记；不同弹族仍有歧义时保留泛称。

手工 `-names` 具有最高显示优先级，但显示名称本身不是型号证据。型号识别不改变飞行轨迹、INS 标签、干扰物或地图位置。

完整固定版本名称目录同时覆盖本局未出现的型号；AAM/AGM 目录范围及重建方式见[导出信息说明](acmi-information.zh-CN.md#空对空导弹型号)。短构造标识可参与同局关联，但不会改变历史 `WT_WeaponID` 表的解码及 SHA 限制。

## 开关与外部数据表

默认使用内嵌表，也可以关闭补全或指定外部 JSON：

```powershell
.\wrpl-acmi.exe -in "D:\Replays\replay.wrpl" -out "D:\Replays\replay.acmi"
.\wrpl-acmi.exe -missile-models off -in "D:\Replays\replay.wrpl"
.\wrpl-acmi.exe -missile-models "D:\missile_models.json" -in "D:\Replays\replay.wrpl"
```

`-missile-models off` 关闭补全表，基础击杀型号识别及独立的制导信息功能仍可运行。外部表必须通过 schema 和枚举校验；数字 ID 规则必须限定在相应回放哈希下，不能作为全局映射。

## 候选与不确定性

ACMI 的 `WT_MissileModelSource`、`WT_MissileModelConfidence` 以及候选、冲突属性记录识别依据。这些是自定义属性，不保证 Tacview 标准遥测面板提供专用仪表。

例如，F-2A 的已知挂载包含 AIM-7M，因此普通 rocket 模板不能一律解释为红外导弹。Su-33 的混合挂载也不能仅凭数量或发射次序，在 R-73、R-27ET 和 R-27ER 之间确定型号。JAS39D、F-15E 等尚缺少直接绑定证据的条目保留候选。

## 历史样例结果

研究样例的完整哈希和逐项依据见[型号证据报告](evidence/missile-models.md)。该样例中，确定型号的导弹由 74/104 增至 81/104，约为 77.9%：

| 样例内 ID | 型号 | 数量 |
| --- | --- | --- |
| 35 | PL-12 | 1 |
| 60 | PL-5E II | 1 |
| 69 | AIM-120A | 4 |
| 157 | AAM-3 | 1 |

其余 23 枚保留候选，置信度分别为 medium 10 枚、low 13 枚。

另一样例 `2026.09.19 16.33.36example.wrpl` 不匹配上述哈希，但通过通用击杀内部名多识别了 1 枚 AAM-3，其 WeaponID 为 39，覆盖数由 10/106 增至 11/106。这也说明同一型号在不同回放中可以使用不同数字 ID。

既有比较覆盖两份回放的 130,558 条位置记录，未发现非预期变化；关闭补全时，研究样例的 ACMI 和 CSV 与当时基线逐字节一致，错误哈希的外部表也未被应用。这些是历史回归结果，不代表所有回放的识别率。
