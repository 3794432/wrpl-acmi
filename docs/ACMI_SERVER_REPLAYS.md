# 服务器回放分片导出

新版 `wrpl-acmi.exe` 支持把同一场服务器回放的分片文件夹作为输入，直接输出 ACMI，无需拼接成中间 WRPL；已下载部分缺少尾片时也可转换，并会标明回放不完整。

## 拖拽

1. 从官网把同一场的 `.wrpl` 分片放入一个独立文件夹；已有的部分下载也可以直接转换。
2. 将整个文件夹拖到 `run.bat`，也可拖到 EXE。
3. 默认在运行目录生成 `<文件夹名>.acmi`；结束标记缺失时生成 `<文件夹名>.partial.acmi`，并在 ACMI 中保留 Incomplete 标记。只拖一个文件夹，不要同时选中多片拖入。

普通客户端单文件 WRPL 的拖拽用法保持不变。原服务器回放的单个分片仍需放进文件夹读取。导出器根据文件头排序，因此文件名不需要手工改序。

## 命令行

```powershell
./wrpl-acmi.exe -in "./server-replays/4ad212e800569482"
```

未指定 `-out` 时，完整分片集生成 `<文件夹名>.acmi`；尾部未结束的分片集生成 `<文件夹名>.partial.acmi`。

当前不直接接收网页链接或 ZIP；先下载并解压分片。不同场次分开存放，不要混在同一目录中。

## 完整性与内存

读取前检查服务器标记、会话、版本、分片编号、重复、缺片和压缩数据完整性。尾部未结束默认导出已有部分并标记不完整；混入其他场次、分片 0 缺失、必需中间分片缺失、重复或压缩损坏时停止并指出问题。输入文件保持不变。

目录读取逐片打开和解压，不把所有原始分片同时装入内存。输出解析器仍需保存轨迹，最终占用取决于整场规模。目录输入不会套用某个客户端单文件回放专属的型号 ID 表；击杀证据和精确型号别名照常使用。

轨迹覆盖仍取决于服务器回放中实际记录的包和已支持的协议，不会补造缺失轨迹。INS、导弹制导类型、估算干扰物和 Atlas 地图的原有证据语义保持不变。

## 尾部未结束时

默认直接导出已下载部分，无需额外参数：

```powershell
./wrpl-acmi.exe -in "./server-replays/4ad212e800569482"
```

未指定 `-out` 时使用 `.partial.acmi` 后缀。部分回放会在 ACMI 的全局属性和说明中标注 Incomplete，不能据此判断整场最终结果。需要恢复严格检查时使用 `-allow-incomplete=false`；混入其他场次、分片 0 缺失、必需中间分片缺失、重复或压缩损坏仍会报错。

本次用户链接对应的下载集有 35 片（0..34），共 13,616,930 字节。最后一片仍以 NextSegment 结束且没有 EndMarker，下一地址返回 404，所以只能按“不完整回放”导出已有部分，不能称为整场回放。

## 本次验证

普通客户端样例与此前版本逐字节一致（1,196 tracks / 79,664 个位置样本）。真实服务器分片的已有部分导出为 55 架飞机、2 枚导弹、215,156 个位置样本，部分机型和两枚导弹的具体型号仍未识别。缺尾目录现在默认导出 `.partial.acmi` 并保留 Incomplete 标记，`-allow-incomplete=false` 可恢复严格拒绝；服务器单片和多文件拖入仍会明确拒绝。全部 Go 测试通过；真实导出受 2 GiB Job 硬限制，峰值进程 Commit 为 469,565,440 字节（约 448 MiB）。未进行 Tacview 图形界面验证。
