# 服务器回放分片导出

[导出指南](acmi-export.zh-CN.md) · [项目说明](../README.zh-CN.md)

导出器可以直接读取同一场服务器回放的分片目录，无需先拼接成中间 WRPL 文件。缺少尾部的回放默认也可导出，但结果会明确标注为不完整。

## 准备输入

从回放网站下载分片后，将同一场的 `.wrpl` 文件放入独立目录。ZIP 文件需先解压；导出器不直接接受网页链接或压缩包。

分片按文件头中的编号排序，无需修改文件名。不要混放其他场次的文件，也不要将单个服务器分片作为普通客户端回放输入。

## 执行导出

```powershell
.\wrpl-acmi.exe -in ".\server-replays\4ad212e800569482"
```

也可以将整个目录拖到 `wrpl-acmi.exe` 或发布包的 `run.bat` 上。一次只提供一个目录，不能同时选择多个分片拖入。客户端单文件回放仍可单独拖放。

未指定 `-out` 时，输出写入当前工作目录；`run.bat` 会先将工作目录切换为发布包目录。

| 分片状态 | 默认输出 |
| --- | --- |
| 完整回放 | `<目录名>.acmi` |
| 尾部缺少结束记录 | `<目录名>.partial.acmi`，并在全局属性及说明中标注 Incomplete。 |

## 完整性检查

读取前会检查服务器标记、会话、版本、分片编号和压缩数据。分片 0 缺失、中间分片缺失、重复分片、场次混杂或压缩损坏都会停止导出，并报告原因。输入文件不会被改写。

只有缺少尾部时，默认的 `-allow-incomplete=true` 才允许导出已有部分。若必须取得完整回放，可使用：

```powershell
.\wrpl-acmi.exe -in ".\server-replays\4ad212e800569482" -allow-incomplete=false
```

部分回放只能呈现已记录的片段，不能据此判断整场最终结果。显式指定 `-out` 会使用该文件名，但不会取消 ACMI 内的不完整标记。

## 内存与数据覆盖

目录按片打开和解压，不会同时加载所有原始分片。解析后的轨迹仍需保存在内存中，因此最终占用取决于对局规模。

目录输入不会套用仅绑定某个客户端单文件哈希的型号 ID 表；通用的击杀证据和精确内部名别名仍可使用。轨迹覆盖取决于回放中实际记录的数据及已支持的协议，缺失部分不会被合成补齐。

## 历史样例验证

既有验证使用了一组 35 个分片（0 至 34）、共 13,616,930 字节的服务器回放。最后一片以 NextSegment 结束，没有 EndMarker，后续下载地址返回 404，因此该样例只能按部分回放处理。

该样例导出 55 架飞机、2 枚导弹和 215,156 个位置样本，部分机型及两枚导弹的具体型号未能识别。在 2 GiB Windows Job Object 限制下，峰值进程 Commit 为 469,565,440 字节，约 448 MiB。

当时的客户端回归样例保持逐字节一致，共 1,196 条轨迹、79,664 个位置样本；相关 Go 测试通过。以上是特定样例的历史结果，不是当前环境的测试报告，也不包含 Tacview 图形界面验证。
